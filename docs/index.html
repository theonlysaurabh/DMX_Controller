Audio-Reactive DMX Lights

One song. Every beat gets its own colour.

An ESP32 plays a pre-analysed audio track back as DMX, through a TTL-to-RS-485 module. Brightness follows the flow of the music, colours follow the instruments, and red, green and blue never blend into white.

From audio file to light show

There is only one track, so the show is worked out ahead of time and tuned until it looks right. Nothing is analysed live.

  1. Analyse offline

    Split the track into bands, find the beats and measure the energy of the song.

  2. Choose the colour

    For each beat, the strongest band picks one colour. The rest stay low.

  3. Build DMX frames

    Colour goes to channels 1 to 3, brightness to the master dimmer on channel 7.

  4. Play back

    The ESP32 streams the frames at 250 kbaud, in step with the audio.

The colour rule

Early versions mixed every band into red, green and blue at once. The lights looked white all the time. The fix is simple.

One colour takes priority on each beat.

Different instruments map to different colours.

A baseline level keeps the lights on between beats.

White appears only when it is asked for.

Wiring

Only TX is used. DMX here is send-only. If the light does not respond, swap A and B on the module.

ESP32 TX   -> module DI
ESP32 GND  -> module GND -> DMX pin 1
module DE+RE tied high (transmit)
module B   -> DMX pin 3 (Data +)
module A   -> DMX pin 2 (Data -)

DMX signal

Standard DMX512 timing is used for every frame.

Baud rate   250,000
Format      8 data bits, no parity, 2 stop bits
Frame       break, mark-after-break, start code 0,
            then channel values 0 to 255
